=== NetApp ONTAP 対応の Amazon FSX



==== イニシエータグループ図の改良

「クライアントアクセス管理」ページに表示される、ブロックデバイスのイニシエータグループを示す図に、ホストに関する詳細情報が追加されました。図中のホストにカーソルを合わせると、ホスト名、インスタンスID、ワークロードタイプ、リージョン、iSCSI修飾名（IQN）などのホストの詳細が表示されます。



==== Well-Architectedの問題に対するメール機能の強化

新しいメールデザインでは、Workload Factoryが検出した構成上の問題について、より詳細な情報とコンテキストを提供します。メールには、分析されたリソースの数、警告または重大な問題があるリソースの数、およびそれらの問題の内容が記載されています。また、このメールにはFSx for ONTAPのWell-Architectedダッシュボードへのリンクも記載されているため、問題をすぐに解決できます。



==== 優れた設計のダッシュボード機能強化



===== 選択された構成チェックのサポート

選択した構成に対して手動で分析を実行することで、関心のある構成のみを分析し、待ち時間を短縮できます。



===== 優れたアーキテクチャ分析における新たな推奨事項

Workload Factory は、FSx for ONTAP ファイルシステムの適切なアーキテクチャ分析に以下の構成を含めるようになりました：

ストレージワークロードの場合：

* *ホストをフェイルオーバーノードに接続*：信頼性を確保するため、アクティブ / パッシブのFSx for ONTAPファイルシステムでホストがフェイルオーバーノードに接続されているかどうかを確認します。
* *ホストを優先ノードに接続*：ホストがパフォーマンス効率のために優先ノードを使用してブロックデバイスに接続されているかどうかを確認します。
* *ARP/AIの複数デバイス検出のギャップ*：ボリュームにブロックデバイスが1つだけ接続されている場合に、ARP/AIは完全な保護範囲を提供します。ボリュームに複数のブロックデバイスが接続されている場合、Workload Factoryはブロックデバイスを新しいボリュームに移動し、各ボリュームにブロックデバイスが1つだけ存在するようにします。
* *クローンクリーンアップ*：ストレージ使用量を最適化し、コストを削減するために削除できる、30日以上前のボリュームクローンがあるかどうかを確認します。
* *igroup OSとホストの一致*：イニシエータグループ（igroup）のオペレーティングシステムがホストのオペレーティングシステムと一致しているかどうかを確認し、I/Oやパフォーマンスの問題を防止します。


Kubernetesワークロードの場合：

* *QoS設定*：パフォーマンス効率を高めるために、Kubernetesの永続ボリュームがONTAP QoSポリシーで保護されているかどうかを確認します。
* *専用KubernetesストレージVM*：ファイルシステムがKubernetesワークロードに専用のストレージVMを使用しているかどうかを確認し、分離性を向上させ、ストレージ管理を簡素化します。
* *専用のKubernetesエクスポートポリシー*：各Kubernetes永続ボリュームに、クラスターのワーカーノードからのアクセスのみを許可する専用のエクスポートポリシーがあるかどうかを確認します。
* *Kubernetes iSCSIバックエンドの双方向CHAP*：Trident iSCSIバックエンドでセキュリティのために相互CHAP認証が有効になっているかどうかを確認します。
* *アプリケーションストレージVMでの `showmount`の無効化*：クライアントがアクセスできないエクスポートを一覧表示するのを防ぐため、アプリケーションストレージVMで `showmount`が無効になっているかどうかを確認します。


データベースワークロードの場合：

* *SAP HANAスナップショットポリシー*：アクティブなデータベースデータのストレージコストを削減し、パフォーマンスを向上させるために、SAP HANAボリュームのスナップショットポリシーが「なし」に設定されているかどうかを確認します。
* *MySQLスナップショットポリシー*：アクティブなデータベースデータのストレージコストを削減し、パフォーマンスを向上させるために、MySQLボリュームのスナップショットポリシーが「なし」に設定されているかどうかを確認します。
* *PostgreSQLスナップショットポリシー*：アクティブなデータベースデータのストレージコストを削減し、パフォーマンスを向上させるために、PostgreSQLボリュームのスナップショットポリシーが「なし」に設定されているかどうかを確認します。




===== 構成の現在の値と推奨値

適切に設計されたダッシュボードでは、最適化されていない一部の構成について、現在の値と推奨値を確認できます。これは、修正する前に推奨される値を示しています。

* コールドデータ階層化
* Snapshot ポリシー
* SSDの容量余裕




==== コスト改善



===== コスト予測と分析

コスト予測機能を使用して、FSx for ONTAPファイルシステムのコストを予測できるようになりました。これは、予算計画を立て、リソースを効果的に最適化するのに役立ちます。また、コストや利用パターンに関する分析結果を確認することで、コスト最適化の機会を特定することもできます。



===== AWS コストおよび使用状況レポート（CUR）

Workload Factoryは、お客様所有のS3バケットに配信される詳細な請求記録を提供するために、AWS Cost Explorerの代わりにAWS Cost and Usage Reports（CUR）を使用するようになりました。CURはより詳細なコスト情報を提供し、高度なFinOps、チャージバック、およびコスト配分のユースケースの基盤として機能します。



==== ストレージVM移行の改善

Workload Factoryは、ストレージVMの移行に関して、ユーザーインターフェース内でより詳細なガイダンスを提供します。これには、移行を本番環境に導入する前に、段階的な手順説明とテスト実行が含まれます。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-replication.html["ストレージVM移行について詳しくはこちらをご覧ください"]



==== レプリケーション遅延メール通知の改善

関連するレプリケーション遅延イベントが多数発生した場合、Workload Factoryはそれらを自動的に1つのメール通知に統合するため、通知が多すぎて混乱することはありません。



==== 自動容量管理機能の強化

Workload Factoryに容量の自動管理を依頼する前に、自動容量管理通知を有効にして機能を試用できるようになりました。ファイルシステムの容量が少なくなると、通知されます。



==== スループット決定ポイント

クライアントのスループットに関する推奨事項と、自動化の決定ポイントを確認できるようになりました。決定ポイントにカーソルを合わせると、現在のSKUと推奨SKU、または一定期間内に違反した指標（%）などの詳細情報が表示されます。



==== 分類に関する顧客管理型Bedrockサポート

Workload Factoryでは、ワークロードのタグ付け分類に独自のAmazon Bedrock環境を使用できるようになりました。独自のBedrockエンドポイントと認証情報を提供することで、分類リクエストを独自のBedrock構成を通して実行させることができます。

=== VMwareワークロード



==== EVS TCO 計算ツールにおける i7i.metal-24xl および i7i.metal-48xl インスタンスのサポート

EVSのTCO計算ツールが、クラスターホストとしてAWSのi7i.metal-24xlおよびi7i.metal-48xl EC2インスタンスをサポートするようになりました。i4i.metal構成と比較して、i7i.metal-24xlインスタンスは、コンピューティングのEVS初期コストを約33%、vSANストレージのEVS初期コストを約25%削減します。

この計算ツールは、すべてのインスタンスタイプを比較し、最もコストの低いオプションを自動的に選択します。新しい比較セクションでは、EVSホストの構成を並べて表示することで、ニーズに最適な設定をより簡単に選択できます。

link:https://docs.netapp.com/us-en/workload-vmware/calculate-evs-savings.html["EVSの推定節約額を計算する"]

=== NetApp ONTAP 対応の Amazon FSX



==== AWSサービス向けワークロードタグ付け検出機能の拡張

Workload Factory は、ワークロードのタグ付け対象となる AWS サービスをさらに多く検出できるようになり、タグ付け可能なリソースのサポートが拡大しました。Amazon EKS および Amazon WorkSpaces リソースを検出し、タグ付けシステムに追加することで、タグ付けに利用できるようになりました。



==== コストダッシュボードの機能強化

コストダッシュボードに、組織の支出概要を示すコストエグゼクティブサマリーセクションが追加されました。これにより、コストを迅速に把握し、管理できるようになります。Workload Factory の AI アシスタントである Ask Me は、お客様のコストデータに基づいて、より詳細な分析結果や推奨事項を提供できます。Ask Me を利用すれば、コスト最適化のための詳細な説明や提案を受けることができます。

さらに、コストデータを1つ以上のファイルシステム、およびファイルシステム内の1つ以上のボリュームでフィルタリングすることもできます。フィルターを適用すると、Workload Factoryには以下が表示されます：

* 月額の推定総費用
* GiB/月あたりの推定コスト
* サービスごとの詳細な費用内訳


ファイルシステムおよびボリュームレベルのコスト配分を除き、すべてのコスト情報はAWS Cost Explorer APIから直接取得されます。ファイルシステムおよびボリュームレベルのコスト配分はWorkload Factoryが推定します。



==== 適切に設計されたダッシュボードへのアクセス

Workload Factory コンソールのメインメニューから、またはファイルシステム内から、Well-architected ダッシュボードにアクセスできます。メインメニューから Well-architected ダッシュボードを見つけるには、メインメニューを選択し、次に「Well-architected」を選択します。

image:well-architected-menu-option.png["Workload Factory コンソールの Well-architected メニューオプション"]



==== 優れたアーキテクチャ分析における新たな推奨事項

Workload Factory は、FSx for ONTAP ファイルシステムの適切なアーキテクチャ分析に以下の構成を含めるようになりました：

* *ボリューム領域管理の設定*：FSx for ONTAP ボリュームの協調ボリューム領域管理を有効にすることを推奨します。
* *FSx と AWS MGN の統合*：選択した FSx for ONTAP ファイルシステムに必要な AWS MGN 準備構成を適用することを推奨します。


link:https://docs.netapp.com/us-en/workload-fsx-ontap/configuration-analysis.html["FSx for ONTAP ファイルシステムのベストプラクティス推奨事項の詳細をご確認ください。"]



==== ボリュームエクスプローラーの機能強化

Volumes explorer は、Workload Factory コンソールの中心的な場所であり、さまざまなファイルシステムにわたるすべてのボリュームを表示および管理できます。各ボリュームのパフォーマンス、使用状況、保護状態など、各ボリュームに関する詳細情報を提供します。今回のリリースにおける機能強化には、ワークロードの選択、ボリュームのレイテンシ表示、およびボリュームの ARP/AI ステータスが含まれます。



===== ボリュームエクスプローラーはワークロードの選択をサポートします

Workload Factoryは、ボリュームの特性と使用パターンに基づいて、デフォルトでワークロードを選択します。ボリュームエクスプローラーから、1つまたは複数のボリュームのワークロードを変更できるようになりました。



===== ボリュームエクスプローラーはボリュームのレイテンシを表示します

ボリュームエクスプローラーは、ボリュームのレイテンシの状態を「未設定」、「しきい値内」、「しきい値超過」の3つのステータスで表示します。これらのステータスは、ボリュームレベルでのパフォーマンスのボトルネックを特定し、修正するのに役立ちます。

==== Workload Factory向けAIエージェント

Workload Factory AIOpsはAIを活用して環境を分析し、改善策を提案します。承認すれば、設定した認証情報と権限を使用して操作を実行することもできます。AIエージェントは、お客様の環境を分析し、Workload FactoryとSlackにおけるリスクの発見、ワークロードの改善、および問題のトラブルシューティングを支援します。

「Ask Me」の新しい「エージェントを探す」セクションで、AIエージェントにアクセスできます。デフォルトでは、エージェントは読み取り専用モードで実行され、推奨事項と分析結果を提供します。

*エージェント設定*を使用して、エージェントの動作を制御します。以下の操作が可能です：

* 読み取り専用モードまたは読み書きモードを選択してください
* エージェントが使用できる認証情報を選択する
* カスタム指示を追加する
* 詳細回答の表示方法を調整する


これらの追加コントロールにより、可視性と監視機能が向上します。読み書きモードでは、エージェントはAWS、ONTAP、またはサポートされているAPIに変更を加える前にお客様の承認を得る必要があります。また、応答に表示される詳細情報のレベルを選択することもできます。これには、エージェントの推論に関する情報や、Slackの場合はエージェントが使用したツールのアクティビティに関する情報も含まれます。

エージェントは、複数アカウント環境にも対応しており、セットアップも簡単です。単一のエージェントで、複数の認証情報を使用して複数の AWS アカウントを安全に横断的に操作できます。

link:https://docs.netapp.com/us-en/workload-setup-admin/learn-agent.html["AIエージェントについて学ぶ"]

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-agent-settings.html["エージェント設定の管理"]

アップグレード手順は「リンク」ページからご覧いただけます。この手順書では、Lambda リンクイメージを手動で更新する方法と、利用可能な場合に自動アップグレードを有効にする方法について説明しています。リンクを最新の状態に保つことで、最新の機能を利用できるようになり、既知の問題が修正され、最新のセキュリティアップデートが適用されます。

=== NetApp ONTAP 対応の Amazon FSX



==== リンク作成はリンクページから利用できます

管理メニューの「リンク」ページから直接リンクを作成できるようになりました。これは、FSx for ONTAP インベントリページおよびファイルシステム概要ページに加えて利用できます。

link:https://docs.netapp.com/us-en/workload-setup-admin/create-link.html["リンクの作成について詳しくはこちらをご覧ください"^]。



==== ワークロードの特定

* Workload Factory は、別のリージョンにデプロイされた FSx for ONTAP ストレージに接続されたホストのワークロードを識別できるようになりました。
* ワークロード検出ロジックの改善により、より多くのワークロードタイプを検出できるようになり、検出結果の精度が向上しました。




[[database-workloads]]
=== データベースワークロード



==== 貯蓄計算ツールのアップデート

FSx for ONTAP ファイルシステム上のデータベースワークロードにおける Microsoft SQL Server ワークロードの実行コストのさまざまな要素（ストレージ、コンピューティング、SQL ライセンス、スナップショット、クローンなど）を、Elastic Block Store （EBS）、FSx for Windows File Server、およびオンプレミスストレージと比較できます。この比較には、表示、計画、分析の権限のみを使用します。

* link:https://docs.netapp.com/us-en/workload-databases/explore-savings.html["データベースワークロードのコスト削減策を探る"]
* link:https://docs.netapp.com/us-en/workload-setup-admin/permissions-reference.html#permissions-for-database-workloads["データベースワークロードの権限"^]

=== NetApp ONTAP 対応の Amazon FSX



==== ボリュームエクスプローラーで利用可能なボリューム操作

ボリュームに関するすべての操作は、1つまたは複数のボリュームに対して、ボリュームエクスプローラーから直接利用できます。これにより、ボリュームレベルの操作をより迅速に実行できるようになります。ボリューム操作には、ボリューム設定の変更、スナップショットの管理、およびボリュームエクスプローラーを離れることなく実行できるその他のボリュームタスクが含まれます。これらの操作は、FSx for ONTAP ファイルシステムの概要にある「ボリューム」タブからもアクセスできます。
