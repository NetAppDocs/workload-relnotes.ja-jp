==== ウェルアーキテクテッド分析における Oracle および Microsoft SQL Server の構成変更

複数のデータベース構成が統合され、適切なアーキテクチャ分析において以下の構成に名称変更されました。

* *ブロックデバイス領域管理*：スペース リザベーション、スペース割り当て、およびフラクショナルリザーブが含まれます

* *ローカルスナップショットのスケジュール*：スナップショットポリシーが含まれます


link:https://docs.netapp.com/us-en/workload-databases/optimize-overview.html["ワークロードファクトリーにおける構成分析"]



==== データベースのIAMアクセス許可ポリシーを更新しました

データベースのアクセス権限が更新され、機能へのアクセス性が向上し、不要なSSMへのアクセスが制限されました。

表示、計画、および分析の権限は、AWS SSM ドキュメントに限定されます。これらの権限があれば、ホスト、インスタンス、データベースを表示できます。また、リソースの基本的なオンデマンドの Well-Architected 分析を実行することもできます。

操作および修復権限を使用すると、リソースの変更、エラーログの分析、リソースの包括的なウェルアーキテクテッド分析の取得、および構成上の問題の修正を行うことができます。

link:https://docs.netapp.com/us-en/workload-setup-admin/permissions-reference.html["権限リファレンス"^]

===== カスタムダッシュボードの通知

Workload Factoryは、カスタムダッシュボードの準備が完了したとき、または作成が失敗したときに通知するようになりました。

カスタムダッシュボードを作成すると、それを直接表示するためのリンクが記載された通知が届きます。作成に失敗した場合は、カスタムダッシュボードのインベントリへのリンクを含む通知が表示され、再度お試しいただけます。

これにより、ダッシュボードの準備が整ったタイミングが分かりやすくなり、確認や再作成も容易になります。

カスタムダッシュボードに共有設定が追加されました。ダッシュボードは非公開にすることも、チームと共有することもできます。

新しいダッシュボードはデフォルトでは非公開設定になっており、あなた以外には表示されません。ダッシュボードはいつでも公開設定にして、Workload Factoryアカウント内のすべてのユーザーと共有できます。

各ダッシュボードカードには「プライベート」または「パブリック」のラベルが表示されるため、どのダッシュボードが共有されているかをすぐに確認できます。

link:https://docs.netapp.com/us-en/workload-setup-admin/learn-custom-dashboards.html#view-and-share-dashboards["ダッシュボードの表示設定と共有について"]

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-custom-dashboards.html#change-dashboard-visibility["ダッシュボードの共有方法について説明します"]



==== AI機能管理

Workload Factoryの管理画面で以下の設定を行うことで、組織全体におけるAI機能へのアクセスを制御できます。

* NetAppが管理するBedrockを使用します（推奨、デフォルトで有効、月単位のクレジット制限あり）
* すべてのAI機能をオフにする


新しい管理ページでは、これらの設定を1か所で管理できます。

AI機能には、Ask Me、カスタムダッシュボード、ルールビルダー、およびEMS、データベースログ、ボリュームレイテンシ用のアナライザーが含まれます。

AI機能がオフになっている場合、ユーザーにはAIが利用できないというメッセージが表示されます。

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html["AI機能の管理について"]

=== EDAワークロード



==== コスト管理を伴うAIレイテンシ分析

Workload Factoryの管理者として、組織全体におけるAIレイテンシ分析へのアクセスを制御できます。

* *NetApp 管理AIクレジット*：管理者が有効にしている場合は、NetAppが管理するAmazon Bedrockとの統合を通じてAI分析を使用できます。追加の設定は不要です。お客様の月間使用量は、割り当てられた予算によって制限されます。月間利用制限に達すると、AI搭載機能は無効になり、メッセージが表示されます。
* *管理者によって無効化されています*：管理者がAI機能を無効にした場合、AI分析オプションはグレー表示され、機能が無効になっていることを示すメッセージが表示されます。




==== 弾力的なスループット増加管理

EDA概要ページから、選択した1つ以上のFSx for ONTAPファイルシステムのスループット増加動作を管理できるようになりました。

* *モード選択*：*自動*または*推奨*を選択してください。
* *一括更新*：1つまたは複数のファイルシステムを選択し、モードとパラメータの変更を一度に適用します。
* *スループット管理ダイアログの変更*：ダイアログでEDAのデフォルト値を使用してスループット増加設定を編集します。
* *詳細設定*：展開可能な *詳細設定* セクションで、追加のスループット決定パラメータを設定します。
* *テーブルの可視性*：Clusters テーブルに新しい *スループット管理* 列が追加され、列設定から有効にできます。
* *トップカード構成*：上部のカードは、SSD管理と同様に、スループット増加モード構成をサポートするようになりました。


link:https://docs.netapp.com/us-en/workload-eda/task-use-overview-dashboard.html["概要ダッシュボードの使用方法を説明します"^]。

=== NetApp ONTAP 対応の Amazon FSX



==== すべての FSx for ONTAP システムで新しいwell-architectedダッシュボードが利用可能になりました

ウェルアーキテクテッド分析が、NetApp Workload Factory の新しいウェルアーキテクテッドダッシュボードから、FSx for ONTAP ファイルシステムで利用できるようになりました。新しいダッシュボードでは、アカウントやリージョンをまたがるすべてのファイルシステムとその構成を一元的に確認できます。ファイルシステムから「Well-architected」タブにアクセスすると、ポップアップ通知が表示されます。Workload Factory の左側のナビゲーションメニューから「Well-architected」を選択すると、新しいダッシュボードにアクセスできます。

特定のファイルシステムのWell-architected分析には、引き続きアクセスできます。また、ストレージの「Well-architected」メニューオプションからもアクセスできます。



==== ストレージダッシュボードに新しいウィジェットが追加されました

ストレージダッシュボードに、ストレージの使用状況を把握し、最適化する方法を見つけるのに役立つ2つの新しいウィジェットが追加されました。

* *検出された上位ワークロード* タグ付けサービスによって環境全体で検出されたワークロードデータを表示します。ボリュームやブロックデバイスなどの関連する FSx リソースを含む、信頼度スコアが 80% を超えるワークロードを表示します。各ワークロードには、その名前、リソース数、プロビジョニングされた容量、および使用済み容量が表示されます。リソース数（デフォルト）、プロビジョニング済み容量、または使用済み容量で並べ替えることで、最大のワークロードをすばやく特定し、ストレージの使用パターンを把握できます。
* *AIを活用した洞察と観察* 管理対象資産に関するAI生成の洞察を表示します。このウィジェットは、選択した範囲内の資産データを分析し、容量、パフォーマンス、データ保護、レプリケーション、コスト削減、ストレージの傾向など、主要な分野における上位3つの発見事項を強調表示します。


各インサイトには、概要、詳細な調査結果、および推奨アクションが含まれています。インサイトを展開すると、詳細を確認し、深刻度、パフォーマンスの改善、コスト削減の機会に基づいて問題の優先順位を付けることができます。



==== ワークロードタグ付け



===== ワークロードタグ付けのためのAWS Systems Managerとの統合

ワークロードタグ付けサービスは、AWS Systems Managerと連携して、ホストインベントリデータに詳細情報を追加できるようになりました。Workload Factoryは、SSMインベントリ情報を収集および処理することで、ワークロードの識別と分類をより適切に行えるようになりました。AWS SSM属性もタグ付けプロセスに含まれており、ワークロード検出の精度向上に役立てられています。

適切に設計されたダッシュボード内のボリューム関連の設定すべてにおいて、リソーステーブルに「ワークロード」列が追加されました。この列は、Workload Factory が各ボリュームに関連付けているワークロードを示しています。



==== ワークロードタグ付けとAI機能

管理者がAI機能を無効にした場合、ワークロードにはタグ付けされません。Workload Factoryアカウントの設定でAI機能が無効になっている場合、タグ付けサービスはストレージリソース上のワークロードを識別または分類しません。

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html["AI管理について学ぶ"^]。



==== 節約額のスナップショット計算の改善点を確認する

「Explore savings now」では一貫したスナップショット容量計算が使用されるようになったため、FSx for ONTAP の節約額の見積もりに追加のスナップショット容量プール要件が正しく考慮されます。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/explore-savings.html["Amazon Elastic Block Store、FSx for Windows File Server、Elastic File System のストレージ環境におけるコスト削減効果をご確認ください。"]



===== レプリケーション遅延データをCSVファイルにエクスポートする

レプリケーション遅延データをCSVファイルにエクスポートして、スプレッドシートでデータを分析したり、他のユーザーと共有したりできるようになりました。



==== S3アクセスポイントイベント

S3アクセスポイントのイベントを、設定したスケジュールに従ってSNSトピックに送信できるようになりました。各アップデートには、前回のアップデート以降に発生したすべてのイベントが含まれます。

S3 イベントの通知を設定するには、link:https://docs.netapp.com/us-en/workload-fsx-ontap/edit-s3-access-points.html["S3アクセスポイントを編集する"] *Journal table* セクションで *Send S3 events by SNS* を選択します。



==== Volumes ExplorerにONTAPの機能が表示される

ボリュームエクスプローラーのボリュームテーブルに ONTAP 機能が追加されました。これらの機能により、保護範囲、自律型ランサムウェア保護（ARP/AI）ステータス、ストレージ効率、階層化ポリシー、ボリュームの自動拡張など、ボリュームの構成とステータスに関するより詳細な情報が得られます。

==== EVS TCO 計算ツールにおける i7i.metal-24xl インスタンスのサポート

EVSのTCO計算ツールが、クラスターホストとしてAWS i7i.metal-24xl EC2インスタンスをサポートするようになりました。i4i.metal構成と比較すると、これらのインスタンスはEVSの初期コストをコンピューティングで約33%、vSANストレージで約25%削減します。

この計算ツールは、両方のインスタンスタイプを自動的に比較し、最も費用対効果の高いオプションを選択します。新しい比較セクションでは、EVSホストの構成を並べて表示することで、ニーズに最適な設定を簡単に見つけることができます。

=== NetApp ONTAP 対応の Amazon FSX



==== ボリュームエクスプローラー

ボリュームエクスプローラーは、NetApp Workload Factory のすべてのボリュームをシンプルに検索可能な形で表示します。どのボリュームがブロックワークロードまたはファイルワークロードに使用されているかをすばやく確認できます。各ボリュームの論理サイズ、物理的な使用容量、およびストレージ効率化機能（圧縮、重複排除、コンパクション）を使用しているかどうかを確認できます。名前、ステータス（利用可能／失敗）、レイテンシ、サイズ、使用容量、および保護機能でフィルタリングおよび並べ替えができます。



==== レプリケーション遅延に関するメール通知機能の強化

レプリケーション遅延に関するメール通知に、影響を受けるリレーションシップに関する詳細情報が含まれるようになりました。この通知により、影響を受けるリレーションシップを迅速に特定し、Workload Factory コンソールで詳細を確認できます。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/track-replication-delays.html["レプリケーション遅延に関する通知を有効にする"]



==== ブロックデバイス作成機能の強化

Workload Factoryは、ボリュームスナップショットからのブロックデバイスの作成をサポートしています。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-block-device.html["Workload Factory でボリュームスナップショットからブロックデバイスを作成する"]



==== ボリュームとブロックデバイスのワークロードタグ付け

Workload Factoryは、ボリュームとブロックデバイスを、その主要なワークロードまたはアプリケーションに基づいて識別し、タグ付けするようになりました。Microsoft SQL ServerやOracle Databaseなどの定義済みワークロードタグを割り当てるか、アプリケーション用にカスタムタグを作成することができます。タグは個々のリソースに適用することも、接続されているストレージリソースに継承させることもできます。これにより、ストレージ構成をワークロードの要件に合わせ、インシデントの影響を把握し、より効果的にトラブルシューティングを行うことができます。

=== セットアップと管理



==== カスタムダッシュボード

ワークロードと優先順位に合わせたAI搭載ダッシュボードを作成することで、業務のパフォーマンスを簡単に把握できます。固定ビューに頼るのではなく、カスタムダッシュボードを使用することで、最も重要な情報に集中できます。

追跡したい内容を平易な言葉で説明すれば、AIがあなたの要望に基づいてダッシュボードを作成します。例えば、災害復旧の状況、地域ごとの容量とコスト、ストレージ保護のコンプライアンス、その他の運用指標を追跡できます。

カスタムダッシュボードは読み取り専用なので、ストレージやワークロードの設定を変更することはできません。Workload Factoryアカウントのユーザーであれば誰でもこれらのダッシュボードを表示および管理できるため、チーム間で情報を共有し、連携を維持することが容易になります。

link:https://docs.netapp.com/us-en/workload-setup-admin/learn-custom-dashboards.html["カスタムダッシュボードの詳細"]

==== 同期されたレイテンシ、IOPS、スループットのグラフによる高度なレイテンシ分析

レイテンシー分析パネルに、同期されたパフォーマンスグラフを含む *Detailed latency analysis* ページが追加されました。

* *レイテンシグラフ*：レイテンシが時間とともにどのように変化するかを示し、しきい値線と、制限を超えた場合のアラートが表示されます。
* *IOPSグラフ*：1秒あたりの操作数を表示し、しきい値線と過去の制限超過を示すインジケーターも表示します。
* *スループットグラフ*：データ転送速度を表示します（DataReadBytesまたはDataWriteBytes）。フィルターでメタデータを選択した場合、スループットグラフにはデータが表示されません。


すべてのグラフは同じタイムラインを使用し、イベントが読み取りか書き込みかに基づいて、適切な指標を自動的に表示します。

表示を調整することで、レイテンシの急増とIOPSおよびスループットの変化との相関関係を把握できます。違反マーカーとホバー時の詳細情報により、しきい値を超えたタイミングを確認したり、検出された違反に関する主要な指標をレビューしたりできます。

https://docs.netapp.com/us-en/workload-eda/task-analyze-latency-trends.html["複数のグラフを使用してレイテンシーの傾向を分析する方法を説明します。"^]。



==== 遅延通知の頻度を設定する

レイテンシ違反に関するメール通知の受信頻度を選択できるようになりました。

* *毎日通知する（推奨）*：FSx for ONTAP ファイルシステムで新しい問題が発生した場合に通知を受け取ります。


同じファイルシステムで1日に複数回のレイテンシ問題が発生した場合でも、送信されるメールは1通のみです。

Workload Factoryは、ファイルシステムの遅延アラートを送信した後、そのファイルシステムに対して次のアラートを送信するまで24時間待機します。

* *レイテンシ違反が発生した場合の通知（20分ごと）*：違反が検出された場合、最大20分ごとに通知を受け取ります。


遅延の問題を通知しつつメールの量を減らすため、デフォルトでは毎日の通知が有効になっています。遅延監視の設定時やしきい値設定の編集時に、通知設定を変更できます。

https://docs.netapp.com/us-en/workload-eda/task-configure-latency-monitoring.html["レイテンシ監視の設定方法を確認する"^]。
