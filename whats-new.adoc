=== セットアップと管理



==== カスタムダッシュボードの更新

カスタムダッシュボードを使えば、作業管理がより簡単になります。

カタログから、指標、グラフ、期間などを含むダッシュボードを直接編集できます。

ダッシュボードを編集すると、Workload Factoryは以前のプロンプトとメッセージとともにチャットを再開します。その後、ダッシュボードを更新したり、変更を保存したり、以前のバージョンに戻したりできます。

ダッシュボードを編集できるのは、ダッシュボードの作成者のみです。編集中は、保存するまで他のユーザーは変更内容を確認できません。

ダッシュボードカタログに、カテゴリやステータスに基づいてダッシュボードをすばやく見つけるのに役立つフィルターが追加されました。

管理者がAI機能を無効にした場合、または月間クレジット限度額に達した場合、ダッシュボードの作成と編集は無効になります。

=== NetApp ONTAP 対応の Amazon FSX



==== AWSサービス向けワークロードタグ付け検出機能の拡張

Workload Factory は、ワークロードのタグ付け対象となる AWS サービスをさらに多く検出できるようになり、タグ付け可能なリソースのサポートが拡大しました。Amazon EKS および Amazon WorkSpaces リソースを検出し、タグ付けシステムに追加することで、タグ付けに利用できるようになりました。



==== コストダッシュボードの機能強化

コストダッシュボードに、組織の支出概要を示すコストエグゼクティブサマリーセクションが追加されました。これにより、コストを迅速に把握し、管理できるようになります。Workload Factory の AI アシスタントである Ask Me は、お客様のコストデータに基づいて、より詳細な分析結果や推奨事項を提供できます。Ask Me を利用すれば、コスト最適化のための詳細な説明や提案を受けることができます。

さらに、コストデータを1つ以上のファイルシステム、およびファイルシステム内の1つ以上のボリュームでフィルタリングすることもできます。フィルターを適用すると、Workload Factoryには以下が表示されます：

* 月額の推定総費用
* GiB/月あたりの推定コスト
* サービスごとの詳細な費用内訳


ファイルシステムおよびボリュームレベルのコスト配分を除き、すべてのコスト情報はAWS Cost Explorer APIから直接取得されます。ファイルシステムおよびボリュームレベルのコスト配分はWorkload Factoryが推定します。



==== 適切に設計されたダッシュボードへのアクセス

Workload Factory コンソールのメインメニューから、またはファイルシステム内から、Well-architected ダッシュボードにアクセスできます。メインメニューから Well-architected ダッシュボードを見つけるには、メインメニューを選択し、次に「Well-architected」を選択します。

image:well-architected-menu-option.png["Workload Factory コンソールの Well-architected メニューオプション"]



==== 優れたアーキテクチャ分析における新たな推奨事項

Workload Factory は、FSx for ONTAP ファイルシステムの適切なアーキテクチャ分析に以下の構成を含めるようになりました：

* *ボリューム領域管理の設定*：FSx for ONTAP ボリュームの協調ボリューム領域管理を有効にすることを推奨します。
* *FSx と AWS MGN の統合*：選択した FSx for ONTAP ファイルシステムに必要な AWS MGN 準備構成を適用することを推奨します。


link:https://docs.netapp.com/us-en/workload-fsx-ontap/configuration-analysis.html["FSx for ONTAP ファイルシステムのベストプラクティス推奨事項の詳細をご確認ください。"]



==== ボリュームエクスプローラーの機能強化

Volumes explorer は、Workload Factory コンソールの中心的な場所であり、さまざまなファイルシステムにわたるすべてのボリュームを表示および管理できます。各ボリュームのパフォーマンス、使用状況、保護状態など、各ボリュームに関する詳細情報を提供します。今回のリリースにおける機能強化には、ワークロードの選択、ボリュームのレイテンシ表示、およびボリュームの ARP/AI ステータスが含まれます。



===== ボリュームエクスプローラーはワークロードの選択をサポートします

Workload Factoryは、ボリュームの特性と使用パターンに基づいて、デフォルトでワークロードを選択します。ボリュームエクスプローラーから、1つまたは複数のボリュームのワークロードを変更できるようになりました。



===== ボリュームエクスプローラーはボリュームのレイテンシを表示します

ボリュームエクスプローラーは、ボリュームのレイテンシの状態を「未設定」、「しきい値内」、「しきい値超過」の3つのステータスで表示します。これらのステータスは、ボリュームレベルでのパフォーマンスのボトルネックを特定し、修正するのに役立ちます。



===== ボリュームエクスプローラーは、すべてのファイルシステムにわたるボリュームのARP/AIステータスを表示します。

ボリュームエクスプローラー画面に、すべてのファイルシステムにわたるボリュームのNetApp Autonomous Ransomware Protection with AI（ARP/AI）ステータスを表示するカードが追加されました。このカードには保護されているボリュームの数が表示され、リスクにさらされているボリュームがあるかどうかが示されます。このカードから「攻撃を分析」して、潜在的なランサムウェアの脅威を調査し、データを保護するための適切な対策を講じることができます。

image:volumes-explorer-arp-ai-card.png["スクリーンショットは、ボリュームエクスプローラー画面に新しいカードが表示され、すべてのファイルシステムにわたるボリュームの ARP/AI ステータスが表示されている様子を示しています。このカードには、保護されているボリュームの数とリスクにさらされているボリュームの数が示されています。ユーザーは「Analyze attacks」というテキストを選択することで、疑わしい攻撃を調査し、データを保護するための適切な措置を講じることができます。"]

link:https://docs.netapp.com/us-en/workload-fsx-ontap/ransomware-protection.html["ランサムウェア対策について詳しくはこちらをご覧ください。"]



==== 正常でないレプリケーション関係に関するメール通知

レプリケーション関係のステータスが*異常*の場合、Workload Factoryは、その状態が続く限り24時間ごとにメール通知を送信します。関係が正常な状態に戻ると、リマインダー通知は停止します。



==== AIOps 向け制限付き ONTAP 認証情報のサポート

Workload Factory は、FSx for ONTAP ファイルシステムに対して、プライマリと制限付きの 2 種類の ONTAP 認証情報をサポートしています。デフォルトでは、ファイルシステムはプライマリ ONTAP 認証情報を使用します。制限付き認証情報は、Rule builder、カスタムダッシュボード、および AI アシスタントである Ask Me などの AI 運用（AIOps）にのみ使用します。ユーザー名とパスワード、またはシークレット ARN を使用して独自の認証情報を追加し、AIOps 機能へのアクセスを制限できるようになりました。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/manage-file-system-settings.html["FSx for ONTAP ファイルシステムの ONTAP 認証情報を管理する"]



==== ボリューム作成時のワークロード選択

Workload Factory では、ボリューム作成時に*ワークロード*フィールドが追加され、ボリュームに関連付けるワークロードを選択できるようになりました。これにより、ボリュームが作成された時点から、意図したワークロードに最適化されます。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-volume.html["Workload Factory コンソールでボリュームを作成する"]



==== FlexCache 書き込みモードの改善

Workload Factory は、ボリュームに推奨される FlexCache の書き込みモードを認識し、パフォーマンスを最適化するために必要に応じて変更を推奨します。



==== リンクドキュメントのサポート

リンクに関するすべてのドキュメントは、Workload Factory のセットアップおよび管理に関するドキュメントに記載されています。Workload Factory FSx for ONTAP ドキュメントの link:https://docs.netapp.com/us-en/workload-fsx-ontap/links-overview.html["NetApp Workload Factory のリンクについて"] を参照して、セットアップおよび管理に関するドキュメント内の関連ページへのリンクを確認することもできます。

link:https://docs.netapp.com/us-en/workload-setup-admin/create-link.html["Workload Factory コンソールでのリンクの設定方法については、こちらをご覧ください。"^]



==== リージョン間におけるホストとストレージの関係性の検出

NetApp Workload Factoryは、ワークロードタグ付けサービスの一環として、複数のAWSリージョンにまたがるホストとストレージ間の接続を検出する機能をサポートするようになりました。この機能により、リージョン間のIPアドレスのマッピングを含め、リージョンをまたいでホストとストレージリソースを識別してリンクすることができるため、ホストとストレージの関係が正しくタグ付けされ、分類されます。



==== ワークロードとホスト識別精度の向上

Workload Factoryは、ワークロードタグ付けサービスにおいて、ワークロードとホストをより正確に識別および分類できるようになりました。最新の検出方法により、誤分類が減り、より正確なタグ付けと分類結果が得られます。



==== インターフェースにおけるファイルシステムの視認性の向上

Workload Factoryのインターフェースで、ファイルシステムの状態がより分かりやすく表示されるようになりました。ファイルシステムの概要画面から、SSDの容量とスループットの使用傾向、ワークロードの概要、詳細な構成情報を直接確認できます。Workload Factoryは、ワークロードタグ付けサービスにおいて、ワークロードとホストをより正確に識別および分類できるようになりました。最新の検出方法により、誤分類が減り、より正確なタグ付けと分類結果が得られます。

==== Workload Factory向けAIエージェント

Workload Factory AIOpsはAIを活用して環境を分析し、改善策を提案します。承認すれば、設定した認証情報と権限を使用して操作を実行することもできます。AIエージェントは、お客様の環境を分析し、Workload FactoryとSlackにおけるリスクの発見、ワークロードの改善、および問題のトラブルシューティングを支援します。

「Ask Me」の新しい「エージェントを探す」セクションで、AIエージェントにアクセスできます。デフォルトでは、エージェントは読み取り専用モードで実行され、推奨事項と分析結果を提供します。

*エージェント設定*を使用して、エージェントの動作を制御します。以下の操作が可能です：

* 読み取り専用モードまたは読み書きモードを選択してください
* エージェントが使用できる認証情報を選択する
* カスタム指示を追加する
* 詳細回答の表示方法を調整する


これらの追加コントロールにより、可視性と監視機能が向上します。読み書きモードでは、エージェントはAWS、ONTAP、またはサポートされているAPIに変更を加える前にお客様の承認を得る必要があります。また、応答に表示される詳細情報のレベルを選択することもできます。これには、エージェントの推論に関する情報や、Slackの場合はエージェントが使用したツールのアクティビティに関する情報も含まれます。

エージェントは、複数アカウント環境にも対応しており、セットアップも簡単です。単一のエージェントで、複数の認証情報を使用して複数の AWS アカウントを安全に横断的に操作できます。

link:https://docs.netapp.com/us-en/workload-setup-admin/learn-agent.html["AIエージェントについて学ぶ"]

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-agent-settings.html["エージェント設定の管理"]



==== Ask Meでスケジュールされたタスク

Ask Me チャットでプロンプトをカスタマイズして、スケジュールされたタスクを作成できるようになりました。スケジュールされたタスクを使用すると、Ask Me に定期的なチェックを実行させ、定義したスケジュールに基づいてチャットで更新情報を送信するよう指示できます。

プロンプトの例：

* すべての FSx for NetApp ONTAP ファイルシステムの健全性とライフサイクルステータスを 1 時間ごとに確認し、問題を早期に検出します。
* 最新のインベントリを維持するために、アクセス可能なすべてのAWS FSxファイルシステムを1時間ごとに一覧表示します。


link:https://docs.netapp.com/us-en/workload-setup-admin/workload-factory-overview.html#features["Ask Meの詳細"]



==== Ask Meにおけるストレージサポート

Ask Me は FSx for ONTAP および Google Cloud NetApp Volumes をサポートするようになりました。サポートされているストレージ環境全体で、同じチャット機能を使用して回答や情報を得ることができます。

link:https://docs.netapp.com/us-en/workload-setup-admin/workload-factory-overview.html#features["Ask Meの詳細"]



==== 通知の更新

NetApp Console の通知がデフォルトで有効になりました。NetApp Console のユーザーは、追加設定なしに Workload Factory の通知を自動的に受信します。

link:https://docs.netapp.com/us-en/workload-setup-admin/configure-notifications.html["Workload Factory の通知"]



==== リンク作成通知メール

Workload Factory は、認証情報の追加が成功した後、リンク関連付けを完了するように促すようになりました。認証情報によりリソースの検出が可能になりますが、高度な ONTAP 機能を利用するには、検出されたファイルシステムとのリンク関連付けが必要です。メール通知は毎週月曜日に届きます。リンク関連付けが完了すると、通知は停止します。



==== Lambdaリンクのバージョン通知とアップグレードガイダンス

Workload Factoryは、Lambdaリンクが最新の利用可能なイメージを使用していない場合に警告を表示するようになりました。リンクに対して自動アップグレードがサポートされていない場合、新しいバージョンが利用可能になったときに通知が表示されます。

アップグレード手順は「リンク」ページからご覧いただけます。この手順書では、Lambda リンクイメージを手動で更新する方法と、利用可能な場合に自動アップグレードを有効にする方法について説明しています。リンクを最新の状態に保つことで、最新の機能を利用できるようになり、既知の問題が修正され、最新のセキュリティアップデートが適用されます。

自動アップグレードをサポートしていないリンクに対して新しいリンクバージョンが利用可能になった場合、FSx for ONTAP ダッシュボードにアラートが表示されます。

==== ボリュームエクスプローラーで利用可能なボリューム操作

ボリュームに関するすべての操作は、1つまたは複数のボリュームに対して、ボリュームエクスプローラーから直接利用できます。これにより、ボリュームレベルの操作をより迅速に実行できるようになります。ボリューム操作には、ボリューム設定の変更、スナップショットの管理、およびボリュームエクスプローラーを離れることなく実行できるその他のボリュームタスクが含まれます。これらの操作は、FSx for ONTAP ファイルシステムの概要にある「ボリューム」タブからもアクセスできます。

Workload Factoryは、カスタムダッシュボードの準備が完了したとき、または作成が失敗したときに通知するようになりました。

==== AI機能管理

Workload Factoryの管理画面で以下の設定を行うことで、組織全体におけるAI機能へのアクセスを制御できます。

Workload Factoryの管理者として、組織全体におけるAIレイテンシ分析へのアクセスを制御できます。

=== NetApp ONTAP 対応の Amazon FSX



==== すべての FSx for ONTAP システムで新しいwell-architectedダッシュボードが利用可能になりました

ウェルアーキテクテッド分析が、NetApp Workload Factory の新しいウェルアーキテクテッドダッシュボードから、FSx for ONTAP ファイルシステムで利用できるようになりました。新しいダッシュボードでは、アカウントやリージョンをまたがるすべてのファイルシステムとその構成を一元的に確認できます。ファイルシステムから「Well-architected」タブにアクセスすると、ポップアップ通知が表示されます。Workload Factory の左側のナビゲーションメニューから「Well-architected」を選択すると、新しいダッシュボードにアクセスできます。

特定のファイルシステムのWell-architected分析には、引き続きアクセスできます。また、ストレージの「Well-architected」メニューオプションからもアクセスできます。



==== ストレージダッシュボードに新しいウィジェットが追加されました

ストレージダッシュボードに、ストレージの使用状況を把握し、最適化する方法を見つけるのに役立つ2つの新しいウィジェットが追加されました。

* *検出された上位ワークロード* タグ付けサービスによって環境全体で検出されたワークロードデータを表示します。ボリュームやブロックデバイスなどの関連する FSx リソースを含む、信頼度スコアが 80% を超えるワークロードを表示します。各ワークロードには、その名前、リソース数、プロビジョニングされた容量、および使用済み容量が表示されます。リソース数（デフォルト）、プロビジョニング済み容量、または使用済み容量で並べ替えることで、最大のワークロードをすばやく特定し、ストレージの使用パターンを把握できます。
* *AIを活用した洞察と観察* 管理対象資産に関するAI生成の洞察を表示します。このウィジェットは、選択した範囲内の資産データを分析し、容量、パフォーマンス、データ保護、レプリケーション、コスト削減、ストレージの傾向など、主要な分野における上位3つの発見事項を強調表示します。


各インサイトには、概要、詳細な調査結果、および推奨アクションが含まれています。インサイトを展開すると、詳細を確認し、深刻度、パフォーマンスの改善、コスト削減の機会に基づいて問題の優先順位を付けることができます。



==== ワークロードタグ付け



===== ワークロードタグ付けのためのAWS Systems Managerとの統合

ワークロードタグ付けサービスは、AWS Systems Managerと連携して、ホストインベントリデータに詳細情報を追加できるようになりました。Workload Factoryは、SSMインベントリ情報を収集および処理することで、ワークロードの識別と分類をより適切に行えるようになりました。AWS SSM属性もタグ付けプロセスに含まれており、ワークロード検出の精度向上に役立てられています。

適切に設計されたダッシュボード内のボリューム関連の設定すべてにおいて、リソーステーブルに「ワークロード」列が追加されました。この列は、Workload Factory が各ボリュームに関連付けているワークロードを示しています。



==== ワークロードタグ付けとAI機能

管理者がAI機能を無効にした場合、ワークロードにはタグ付けされません。Workload Factoryアカウントの設定でAI機能が無効になっている場合、タグ付けサービスはストレージリソース上のワークロードを識別または分類しません。

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html["AI管理について学ぶ"^]。



==== 節約額のスナップショット計算の改善点を確認する

「Explore savings now」では一貫したスナップショット容量計算が使用されるようになったため、FSx for ONTAP の節約額の見積もりに追加のスナップショット容量プール要件が正しく考慮されます。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/explore-savings.html["Amazon Elastic Block Store、FSx for Windows File Server、Elastic File System のストレージ環境におけるコスト削減効果をご確認ください。"]



===== レプリケーション遅延データをCSVファイルにエクスポートする

レプリケーション遅延データをCSVファイルにエクスポートして、スプレッドシートでデータを分析したり、他のユーザーと共有したりできるようになりました。



==== S3アクセスポイントイベント

S3アクセスポイントのイベントを、設定したスケジュールに従ってSNSトピックに送信できるようになりました。各アップデートには、前回のアップデート以降に発生したすべてのイベントが含まれます。

S3 イベントの通知を設定するには、link:https://docs.netapp.com/us-en/workload-fsx-ontap/edit-s3-access-points.html["S3アクセスポイントを編集する"] *Journal table* セクションで *Send S3 events by SNS* を選択します。



==== Volumes ExplorerにONTAPの機能が表示される

ボリュームエクスプローラーのボリュームテーブルに ONTAP 機能が追加されました。これらの機能により、保護範囲、自律型ランサムウェア保護（ARP/AI）ステータス、ストレージ効率、階層化ポリシー、ボリュームの自動拡張など、ボリュームの構成とステータスに関するより詳細な情報が得られます。
